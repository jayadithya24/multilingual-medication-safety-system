# Neo4j audit — 23 September 2026

Result: not ready to declare correct. This was a code and dataset consistency review, not a clinical validation. No database import, deletion, or credential change was performed.

## Verified and corrected locally

- Removed fabricated graph responses from `backend/app/routes/neo4j.py`. Graph failures previously returned example patients and a Moderate interaction for arbitrary inputs as successful results. They now return HTTP 503 when the service cannot provide data. The full graph's existing CSV fallback remains available.
- Fixed master drug IDs in the CSV graph fallback: it previously produced 60 drug nodes for 30 medicines because display names and lowercase relationship IDs became separate nodes. Regression coverage now requires 30 drug nodes and no dangling links.
- Seven targeted tests passed (graph failures, dataset fallback, and loader ID fallback).

## Blocking and unresolved findings

1. **Live database unavailable.** A read-only connectivity attempt returned `ServiceUnavailable` / unable to retrieve routing information. This does not establish whether the cause is the Aura instance state, network, URI, or credentials. Live records and Cypher execution remain unverified.
2. **Loader does not match current CSV schema.** `neo4j/load_data.py` expects `disease_name` in `drug_disease.csv` (actual column: `disease`), and `interaction_id` in `drug_interactions.csv` (absent). English description/warnings/contraindications are read only from `_en` fields, although the master uses unsuffixed names. These paths will fail or load empty properties.
3. **Loader/query schema mismatch.** The loader creates Drug `drug_name` and Disease `disease_name`; many service queries require `.name`. It uses `HAS_SIDE_EFFECT`, while readers use `CAUSES`. It MATCHes SideEffect nodes without creating them. Thus a successful-looking load would not guarantee usable graphs.
4. **Loader reruns are unsafe for consistency.** It MERGEs nodes on mutable properties and CREATEs relationships on every run. Schema setup submits a file containing multiple statements in one session.run call. These need correction and integration testing before import.
5. **Legacy loaders must not be run as-is.** Both `load_neo4j_data.py` and `neo4j/load_neo4j_data.py` contain database-wide `DETACH DELETE`, hardcoded connection settings, and interaction extraction based on text mentions. Their single-pass loading can miss edges to drugs created later. No legacy loader was executed.
6. **Interaction severity conflict.** The source has 157 rows / 155 unordered pairs, with two repeated pairs. Ibuprofen–Methotrexate has both Moderate and Severe entries. The lookup takes the first match, and focused graph deduplication also takes the first result; neither resolves conflicting evidence. Do not treat ordering as a clinical resolution.
7. **Coverage and evidence limits.** Only 10 source rows are marked in scope for graph import. The interaction CSV has no description, recommendation, or per-pair citation fields. The CSV service generates generic prose, and Neo4j lookup defaults missing severity to Moderate. Neither establishes verified clinical guidance.
8. **Matching and language limitations.** CSV interaction matching uses partial substrings when exact matching fails, potentially selecting a different medicine. Neo4j interaction lookup accepts `lang` but does not translate its result. Reverse-edge completeness differs: details/search use directed relationships while pair lookup is undirected.
9. **Driver lifecycle.** `get_drug_by_id`, `get_diseases`, and `get_drugs_for_disease` create drivers without closing them. Other methods do close their drivers.
